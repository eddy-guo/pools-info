# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Read `STATUS.md` first for the current state, then `docs/SPEC.md`, `docs/PRIMER.md` and `docs/BRIEF.md`; the handoff traps in `docs/SPEC.md` section 7 corrupt data when skipped.
- Validation is `pnpm check` (lint, typecheck, unit tests, web build), `pnpm test:db` against a dedicated test Postgres in `TEST_DATABASE_URL` (never production, never port 5432 by habit; run it on Postgres 17 and 18 because CI is 17 and Railway is 18), and `pnpm test:e2e`. Database suites must report zero skips. `pnpm test:db` runs its integration files concurrently (Node's default is one fewer than the CPU count: three files at once on the public repository's 4-vCPU CI runner, where a read near the reader's 3 s statement budget times out under the other files' load) and ends with serial phases, one node invocation per file: `apps/api/src/broad-explore.scale.test.ts`, whose printed `52k catalog serving` and `52k creators serving` lines in the CI log are the serving-latency numbers that count, `apps/api/src/observed-market.scale.test.ts`, which bounds the raw-copy market read at 21k swaps, `apps/api/src/observed-market-rollups.scale.test.ts`, which bounds the rollup-served pool page at 80k swaps and asserts its fold never spills, `apps/api/src/ledger-market.scale.test.ts`, whose `ledger market serving` line bounds every explore order and the busiest pool page served from the aggregate ledger at production shape (62k pools, 165k pool hours), `apps/api/src/ledger-market.integration.test.ts`, whose few hundred explore reads against both market sources would starve the concurrent files, and `apps/api/src/observed-market.integration.test.ts`, which reads the 21k fixture through the API; both integration files are kept out of the concurrent glob by Node's own quoted `!(observed-market|ledger-market)` pattern. CI's Postgres has JIT and local Homebrew Postgres has not, so never add a `--test-concurrency` flag and keep latency-asserting tests and reads near the budget in those phases (see `docs/BROAD-MARKET-SERVING.md`). The market browser suite is `pnpm test:e2e:market` (needs `TEST_DATABASE_URL`; its ports derive from the base port, pinned with `PLAYWRIGHT_MARKET_PORT` and `MARKET_API_PORT`). `pnpm test:e2e` derives its web server port per copy of the repo (`webServerPort` in `playwright.config.ts`, announced on each run, overridable with `PLAYWRIGHT_WEB_PORT`) and reuses a server already on it, which is your own worktree's: restart it after rebuilding or the suite silently grades the previous build. `pnpm test:e2e -- <files>` does not filter: this pnpm forwards a literal `--` ahead of the args into `playwright test`, so it runs the whole suite; scope a run with `pnpm exec playwright test <files>` instead. A stale `apps/web/.next` makes `pnpm typecheck` fail on a page that no longer exists, because it runs before the build that regenerates `.next/types`.
- To check a page against the production read API, start a second built server with `INDEXER_API_URL=https://api-production-9f93.up.railway.app CHAIN_REFRESH_DISABLED=0 pnpm --filter @pools/web start --hostname 127.0.0.1 --port <port>` and point one spec at it with `PLAYWRIGHT_WEB_PORT=<port> npx playwright test <spec> --workers=1`: the read API's 240 reads per minute budget is global, so parallel workers trip it and the proxy then answers 503 and the pages show their unavailable state in place of production figures. The normal suite grades the production build; set `PLAYWRIGHT_WEB_DEV=1` on a scoped Playwright command when a browser regression specifically needs the development bundle's assertions. `candles.tsx` keeps exact bigint source prices and scales only the floating-point coordinates sent to lightweight-charts, whose development build rejects series values above 2^53/100.

- Layout stability is a product bar, gated by `tests/e2e/layout-stability.spec.ts` at CLS 0; the assertion itself tolerates a cumulative score under 0.001 as measurement noise (a sub-pixel of movement at 390px), so a runner-load flake reporting e.g. 0.0001277 is not a real shift, but anything at or above 0.001 still fails. A CLS failure that only reproduces in a loaded full run (green alone) reproduces deterministically instead of by luck with `const cdp = await page.context().newCDPSession(page); await cdp.send("Emulation.setCPUThrottlingRate", { rate: 8 })` before `goto`; copy the failing spec into a throwaway `tests/e2e/zzz-*.spec.ts` with an instrumented `PerformanceObserver` that dumps each shift source's `tagName`/`classList`/rects, run it, and delete it before committing - never ship the debug dump itself. That suite runs with `CHAIN_REFRESH_DISABLED=1`, so any text a second request writes stays at its first-paint value unless the spec serves that route itself; text that rewraps inside a height-reserved box still shifts. A reserved slot is therefore sized at first paint and never resized by a response: what a page can know before painting decides the height, which is why the pool page carries its screener row in `apps/web/src/lib/pool-row-memory.ts`. A reserved slot whose children wrap at a narrower width (the wallet chart's `.chart-readout`: one desktop line, but its fixed 16ch value and 30ch time slots cannot share a phone-width line) needs its height stated again inside that breakpoint and its region's height re-summed with it, or the box sized for the wide layout clips the narrow one (`globals.css`, the `@container site (max-width: 767px)` block stacks it at 69px in a 272px region; PR 81 had compacted the desktop to 40px and left the phone's three lines in that box). The shift observer only counts nodes inside the viewport (the mobile project is a Pixel 7, 412x839), so a reserved slot below the fold can resolve to a different height and still pass; when you change what sits above one, compare its pending and resolved rects directly (`tests/e2e/leaderboard-labels.spec.ts` shows the pattern). `DESIGN-DELTA.md` records how the reserved slots are sized. A value whose unavailable state renders no text at all (`Change`/`Price` in `ui.tsx` keep it wordless) collapses its own line box, so in a stacked column it drops a whole line as the read resolves and re-centres the column around it (`.mobile-pool-price`'s children hold `min-height: 1lh` for exactly that). React rewrites a cell's plain string or number child in place, and Chrome scores rewritten text whose start moves (any right-aligned cell) as a shift, so a value that replaces a placeholder is wrapped in a fragment or element (the Launches cell in `apps/web/src/components/creators.tsx`), and `Change` in `ui.tsx` keeps its sign, figure and unit as separate children for the same reason, since its pending state is a lone "Pending" text node that a single string child would rewrite in place (the screener's negative change cells scored 0.00007 when it was collapsed to one string); a right-aligned box whose width follows its text moves the same way, so it sits in a fixed track (the wallet's behaviour values). Browser-local state (`following.tsx`, `state.tsx`'s watchlist, `my-wallet.tsx`) reads localStorage through `useSyncExternalStore` with a null server snapshot, so the server paints the unset state and hydration swaps it: whatever it changes is keyed to remount as new nodes, which Chrome never scores, and keeps the width it painted (the "This is my wallet" button holds one label in both states); the traders leaderboard's Show more control uses the same remount-not-resize trick for a different first-paint gap (see the Following bullet above). `/` is prerendered static, so a sorted or `?view=new` URL hydrates over the default head: a right-aligned head whose box changes with the order moves too, which is why the screener's sort arrow sits before its label and out of the flow (`.sort-arrow` in `apps/web/src/app/globals.css`). A `display: flex`/`inline-flex` element drops the whitespace between a bare text run and a following inline child as an edge-collapse (the wallet header's address/last-trade line hit this: `.wallet-last-meta` in `globals.css` stays `display: inline`, a flex item is blockified regardless); a fact that mounts only once a read resolves needs its own fixed-width flex slot from first paint too, or the sibling that shrinks to fit beside it (an ellipsised address) reflows when the fact arrives, which the shift observer scores even though nothing looks different (`.wallet-last-meta-slot`). A `<colgroup>` fixes a `table-layout: fixed` column at first paint against re-renders that don't change data; give it whole pixels, not a `%` width, since a fractional percentage of the panel's own width can round to a different sub-pixel value between layout passes and score as a shift with byte-identical rects in the observer's own before/after log (`apps/web/src/components/product-wallet.tsx`'s positions table).

- `page.clock.fastForward` only fires timers that were already armed when it moved: a client that arms its wait *after* parsing a response (`fetchProduct`'s warming retry) can have the clock advanced past the arming point, leaving the wait scheduled beyond a frozen now where it never fires - a red test that says nothing about the product. Gate each fast-forward on the wait existing, not on the request that precedes it (`recordWarmingWaits`/`warmingWaitArmed` in `tests/e2e/empty-states.spec.ts` record what the page asked the emulated timer for; the wrapper is installed after `clock.install()` so it wraps that timer).
- A Playwright height assertion must wait for the *resolved* rows, never just the rows that are there: `locator.evaluateAll` resolves its nodes in one round trip and runs the measurement in the next, so a re-render in between hands it nodes React has already detached and every rect reads 0. Gate on the resolved marker the way `mobile-rows.spec.ts` does (`[data-row='resolved']`). When a browser assertion fails only in CI, `gh-axi run download` the trace and read its `before`/`after` call spans: they prove what landed inside a call, which the log alone cannot.
- A fake-upstream test for a fetch built on `AbortSignal.timeout()` must not race a bare pending `Promise` with only an abort listener: that timer is unref'd, so Node's test runner can cancel the test as "Promise resolution is still pending but the event loop has already resolved" once nothing else keeps the loop alive (it passes alone and only fails alongside other test files, so it can look like unrelated flakiness). Point the fetch at a real, never-responding local server instead, as `apps/api/src/eth-price.test.ts` and the `deadline()` helper in `packages/token-image/src/index.test.ts` do.
